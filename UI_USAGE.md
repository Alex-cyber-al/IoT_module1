# Звіт про використання ШІ

У цій роботі я використовував штучний інтелект виключно як помічника та технічного консультанта для розв'язання окремих проблем із налаштуваннями. Усі програми, текстові конфігурації та правила автоматизації я писав і налаштовував самостійно.

## 1. Які інструменти використовувалися
* **Назва моделі:** Google AL/Gemini. 
* **Період використання:** 24, 25 жовтня 2026 року.

## 2. Журнал консультацій із ШІ
Я звертався до ШІ за порадами у трьох конкретних моментах, коли виникали труднощі з налаштуванням середовища:

1. **Консультація щодо Docker на Windows:**
   * **Проблема:** Коли я налаштовував безпеку, контейнер Mosquitto не хотів запускатися під Windows і видавав помилку доступу до файлів (код 13, Permission Denied).
   * **Запит до ШІ:** Я запитав, як змусити Docker ігнорувати обмеження прав Windows на папки й автоматично підтягувати базу паролів.
   * **Що підказав ШІ:** Порадив додати рядок `user: "0:0"` (запуск під root-правами) та прописати внутрішні Linux-шляхи для папки з конфігами всередині Docker Compose. Це допомогло запустити брокер.

2. **Консультація щодо синтаксису openHAB 4:**
   * **Проблема:** Я не знав, як правильно прописати розшифровку тексту з формату JSON прямо всередині текстового файлу `.things`.
   * **Запит до ШІ:** Запитав точний приклад рядка для підключення каналу лічильника, щоб він сам діставав значення `power`.
   * **Що підказав ШІ:** Підказав використати конструкцію `transformationPattern="JSONPATH:$.power"`. Я вставив цей параметр у свій файл конфігурації.

3. **Консультація щодо таймерів у правилах:**
   * **Проблема:** За методичкою для відеозахисту треба показати роботу правил автоматично, але реальні таймери на 5 чи 30 хвилин очікування відсутності руху занадто довгі для короткого ролика.
   * **Запит до ШІ:** Запитав, як у правилах на Rule DSL правильно написати короткий таймер на 30 секунд.
   * **Що підказав ШІ:** Надав приклад функції `createTimer(now.plusSeconds(30), [ | ... ])`, яку я використав, щоб прискорити демонстрацію правил для відео.

## 3. Галюцинації ШІ, які я знайшов і виправив особисто
Штучний інтелект кілька разів видавав помилкові рішення (галюцинації), які я виявив під час тестування та виправив самостійно:
* **Помилка з бібліотеками в Python:** ШІ запропонував формулу для гарного коливання цифр лічильника за допомогою синусоїди `math.sin()`, але взагалі забув написати імпорт цієї бібліотеки. Через це мій симулятор спочатку падав із помилкою `NameError: name 'math' is not defined`. Я сам знайшов цей баг і додав рядок `import math` на початку коду.
* **Помилка з регістром літер:** ШІ написав назви пристроїв у правилах з маленької літери (`room1_motion`), а у файлі елементів я створив їх з великої. Через це правила видавали помилку. Я вручну перевірив усі конфіги й перевів назви у верхній регістр (**`Apartment_Power`**, **`Room1_Motion`**), щоб усе збігалося.

## 4. Що зроблено повністю самостійно (Без ШІ)
* Повністю сам розпланував структуру й назви MQTT-топіків (`flat/corridor/...`).
* Вручну прописав матрицю обмежень доступу у файлі **`acl.conf`**, розділивши права на читання та запис для користувачів.
* Сам створив зовнішній вигляд інтерфейсу у файлі **`apartment.sitemap`**, налаштував іконки для датчиків і додав графік `Chart` для відображення споживання енергії за останню годину.
* Самостійно розібрався з критичною системною помилкою, коли на моєму комп'ютері закінчилося місце на диску (C:) до 12 мегабайт, і вручну очистив пам'ять для відновлення роботи системи.

## 5. Висновок
ШІ послужив зручним довідником для уточнення точного синтаксису openHAB та Docker, але всю архітектуру системи, логіку зв'язків між датчиками, налаштування безпеки та виправлення системних збоїв я виконав повністю сам. Код є повністю моїм робочим результатом.
